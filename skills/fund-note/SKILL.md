# fund-note

## 目的与触发场景

承接基金/黄金基金研究咨询，并在用户明确要求时将研究判断沉淀为结构化笔记。研究方法和数据规则统一引用 `fund-research`；本 Skill 不维护账户持仓与交易。

触发示例：
- “这只支付宝债基的风险主要是什么？”
- “比较这只 QDII 和对应的指数基金。”
- “帮我看这个黄金 ETF 联接的底层暴露。”
- “记下这只基金的研究逻辑 / 保存这次结论。”

## 处理流程

1. 识别产品名称、代码、份额类别、平台和类别；读 `domains/invest/fund_universe.json`。若映射缺失，先依据支付宝页面与基金管理人/正式产品资料核验，确认后登记身份及来源；身份不清或代码/名称冲突时先澄清，不按代码格式猜测，不调用股票行情接口。
2. 读取 `skills/fund-research/SKILL.md`，并按品类加载所需 references；尤其按来源规则核对具体基金身份、净值日期、收益期间、费用和风险因素。
3. 先按用户问题给简明结论，再展示支持证据、反方风险、口径限制和待确认信息。具体基金数据须标来源、日期和统计口径；不可用预测净值或二手页面数字装成基金公司披露。
4. **默认不落库**。只有用户明确说“记录/保存/记下研究结论”等，才更新 `domains/invest/data/fund_notes/<YYYY-MM>.json`；“分析一下 / 怎么样 / 值不值得关注”本身不等于保存。
5. 写笔记时明确区分已核实事实、第三方观点、用户提供的想法与分析判断。来源存入 `metrics.evidence`（名称、URL、发布日期、数据截至日期、指标及来源级别）；用户提供的信息标为 `user_screenshot` 或 `user_statement`，不能伪称公开来源。
6. 至少记录 `thesis`、`product_category`、`fund_code`、`fund_name`、`platform`；若是用户自己的假设或尚待验证的信息，在 `note` 标 `[待确认]`。记录可观测的 `kill_criteria`；如当前证据不足以形成证伪条件，写明不足，不造条件。
7. 运行 `python3 scripts/normalize_fund_data.py --check` 并核验写入文件路径。不要改基金持仓或交易记录；用户要求账户更新时转 `fund-position`。
8. 若输出包含具体投资建议、操作条件或仓位建议，按 `fund-research/SKILL.md` 末尾的固定免责声明原文收尾。

## 笔记边界

- 普通咨询不自动记录；研究笔记不是交易信号或买卖清单。
- 不用股票评级、盘口指标、技术止损位、5 元佣金约束来评价场外基金。
- 不能因是黄金主题就省略母 ETF、基准、汇率或重复敞口核对；详细规则见 `fund-research/references/gold-fund.md`。
- 不纳入支付宝账户金、积存金、实物黄金；不自动接入日报、周报、dashboard 或总资产汇总。
