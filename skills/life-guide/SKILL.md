# life-guide

把《高性价比人生指南》（690 条，CC BY 4.0）当成一个可检索的决策库来用。**先查书，再回答**。

## 触发场景

- 「替朋友担保签不签」「戒烟值不值」「这个保健品是不是智商税」
- 「被裁了先做什么」「没钱时能领什么」「这个检查该不该做」
- 「这么做犯法吗」「房东不退押金怎么办」「帮不帮、怎么帮才不把自己搭进去」
- 「划不划算 / 性价比 / 值不值 / 靠谱吗」类的任何抉择

## 检索流程

1. **判主题**：读 [`routing.md`](routing.md)，用问题里的关键词定位到分类与章节文件（也看 `domains/lifeguide/data/categories.json`）。
2. **查条目**：在 `domains/lifeguide/INDEX.md` 里按关键词搜条目编号（人读），或查 `domains/lifeguide/data/index.json`（机读，含 `summary` / `tags` / `audience` / `file`）。
3. **读原文条目**：打开 `index.json` 里 `file` 指向的文件，定位 `### LG-<节>-<条>` 读完整结论。
4. **命中多条时排序**：先按收益量级（大 > 中 > 小），再按成本（不花钱 > 几十元 > 上千元），同成本时按证据等级（A > B > C）。只报最相关的 3–5 条，不要把整节倒出来。
5. **引用作答**：结论照抄条目「结论」字段，**不改写数字和方向**；补上成本与证据等级。

## 引用规范（强制）

回答末尾必须单独一行注明来源，格式：

```
来源：《高性价比人生指南》（eternity4719/HowToLiveBetter，CC BY 4.0）第 <N> 节《<章节名>》第 <M> 条 · 条目编号 LG-<NN>-<MM>
```

- 命中多条就列多条，一行一条。
- 用了「注意」或「争议」内容，也要在正文里说明，不能只挑有利的一句。
- 证据等级必须一起给出（A / B / C），让读者自己判断分量。

## 铁律

1. **不改动原意**：数字、升 / 降方向、适用范围照抄；只做删减不做推断。原条目没有的结论不许补。
2. **没命中就说没命中**：库里没有的相关条目，明确说「指南里没有这一条」，不要拿相邻话题硬套。
3. **边界提示不能省**：
   - 医疗类 → 「具体做不做、怎么做以医生为准」；
   - 法律类 → 「以当地部门和律师的说法为准」，且要提示过程成本（要多久、律师费谁出）；
   - 金钱 / 投资类 → 「不构成投资建议」。
   - 政策类 → 「各地执行不一样，以当地经办部门为准」。
4. **不编造**：不许凭记忆写出条号或数字；查不到就回 `index.json` 复核。
5. **只查不改**：本 Skill 不写 `domains/lifeguide/data/` 下任何文件（那是提炼产物的正本，更新走重跑提炼流程）。

## 与其他 Skill 的关系

- 涉及**每天吃什么、食堂点餐** → 属 operational 范畴，本 Skill 只给原则性条目（如食用油、控盐）。
- 涉及**投资标的选择** → 走 `invest-router` / `stock-research`；本 Skill 只提供「别买什么 / 怎么算账」类的通用条目（第 5 节）。
- 涉及**记录与落库**（吃了什么、练了什么） → 走 `capture-router`，与本 Skill 无关。
