# 基金数据来源与日期纪律

## 来源优先级

1. **基金管理人 / 法定披露**：基金合同、招募说明书、产品资料概要、定期报告、临时公告及基金公司净值页面，作为产品身份、策略、费率、持仓和正式 NAV 的优先依据。
2. **销售平台账户页面**：仅用于用户账户事实、订单状态、份额、成本、申赎申请/确认/到账和页面展示收益；勿将用户隐私写入结构化记录。
3. **第三方基金数据平台/媒体**：可辅助检索和交叉核验；注明平台名称、数据截至日期及“第三方/非一手来源”，关键争议回到管理人或法定披露核实。
4. **分析推断**：明确标 `[判断]` 或 `[假设]`，附计算公式及输入数据，不与披露事实混写。

## 检索与身份核验

- 涉及具体基金/净值/业绩时先使用当前可用的金融检索工具；查询意图保留代码与名称，不传给股票行情接口。
- 若查询结果与代码、名称或类别冲突，停止使用冲突数据，重新核验身份；结果不一致时列出差异而非挑一个静默采用。
- `fund_universe.json` 只存已核实映射。空目录意味着尚未建立用户产品映射，不可用模板示例冒充。身份条目保存核验来源名称及可用的 URL/日期；用户提供截图或口述须标 `user_screenshot` / `user_statement`，不伪称公开来源。

## 每项数据须保存的追溯信息

对正式 NAV、收益、基金规模、经理、前十大持仓、费率、跟踪偏离及货币基金指标，尽量记录：来源名称、URL、发布日期、数据截至日、指标/口径、获取日期。具体数据块可共用来源脚注，但每个关键结论须能对应到来源和时点。

## 时效与缺失

- 正式基金 NAV 在页面可用前可能尚未披露；明确使用“最近可用 NAV（日期）”，不把估值当正式净值。
- QDII、节假日或暂停估值产品需附底层市场日期，必要时说明时区/披露滞后。
- 查询不到某项就标 `[MISSING]` 或“当前来源未覆盖”；陈旧数据标 `[STALE · 数据截至 YYYY-MM-DD]`。不使用训练记忆填数，不以近似值替换。
- 来源网页变化或仅可访问摘要时，注明可核验范围；费率/持仓等重要项优先引用产品原始披露。

## 用户截图

截图可验证用户账户事实，不自动证明产品策略、长期收益或当前基金合同费率。结构化记录只写必要字段，`source` 用 `data/raw/` 下的本地相对路径；不得把原始截图推送到仓库。外部证据写入 `metrics.evidence`，不与 `source` 附件路径混用。
