# fund-router

## 目的与触发

作为 `invest` 域中**支付宝场外基金与黄金基金**的专用入口，负责确认产品类别、平台及用户意图，然后分发到基金业务 Skill。本 Skill 只做路由和必要澄清，不自行研究基金、不修改台账。

触发示例：
- “帮我看支付宝里的这只债基 / QDII / FOF”
- “记录余额宝持仓”或上传支付宝基金持仓、申购/赎回截图
- “黄金基金适不适合我”或“记下这只黄金 ETF 联接的研究逻辑”

## 身份与范围判定

1. 先读 `domains/invest/fund_universe.json`，确认本期产品边界与已核实身份映射。
2. 依据用户明确提及的平台、产品名称、基金合同/页面类型、代码与份额类别等证据识别产品；代码本身不能证明产品身份。目录未登记时，先核验支付宝页面与基金管理人/正式产品资料，再把确认后的代码、名称、平台、类别和身份来源登记入 `products`；冲突时先澄清，不覆盖已有映射。
3. 对支付宝场外基金代码保留字符串与前导零。**禁止**补 `sh` / `sz`，禁止按股票前缀白名单识别，禁止用股票或场内 ETF 行情接口查询场外基金代码。
4. 识别到场内股票、ETF 或 LOF（包括场内黄金 ETF）时交回 `skills/invest-router/SKILL.md`。不要把“基金”字样作为场内/场外的判断依据。
5. “黄金”但未说明产品类型时，先问清是场外黄金基金/ETF 联接、场内黄金 ETF、支付宝账户金/积存金还是实物黄金。账户金、积存金与实物黄金不在本期范围；不可擅自套用基金份额 Schema。
6. 只说“基金”且无法辨别产品类型或平台时，先询问一项最关键的澄清信息；不可依代码前缀猜测。

## 请求分发

| 意图 | 分发目标 | 是否写数据 |
|---|---|---|
| 查询、比较、适配性、风险或配置讨论 | `skills/fund-note/SKILL.md`，并按需引用 `fund-research` | 默认不写 |
| 用户明确要求保存基金研究结论 | `skills/fund-note/SKILL.md` | 写 `fund_notes` |
| 持仓截图、更新份额/成本/净值快照 | `skills/fund-position/SKILL.md` | 更新台账与 `fund_positions` |
| 申购/赎回申请、确认、到账截图或文字 | `skills/fund-position/SKILL.md` | 更新交易记录，必要时修正快照 |
| 股票 / 场内 ETF / 场内 LOF | `skills/invest-router/SKILL.md` | 由股票侧继续处理 |

在执行研究分析时由 `fund-research` 的 references 确定分析范围、口径和数据源；在涉及交易记录时由 `fund-position` 确定如何处理截图、在途状态及落库。研究咨询不应被当成人生指南中的一般“值不值得”问题截走；健康域优先级仍按 `capture-router` 现行规则保留。

## 路由回报

只在有歧义时向用户说明识别依据并提问。确认清楚后，直接交给目标 Skill，不复述全套流程；不在本路由层自行产生买卖建议或填入台账。
