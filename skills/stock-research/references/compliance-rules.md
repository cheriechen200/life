# 合规铁律

> `stock-research` 的参考文件。标的池、可追溯、声明三类规则。

## 一、标的池铁律（机器可校验）

配置源文件：**`domains/invest/universe.json`**。生成任何推荐 / 建仓动作前**必须先读该文件并做前缀校验**。

### 校验顺序

1. **先匹配 deny**：命中即拒绝。
2. **再匹配 allow**：既非 `stock` 也非 `etf` 允许前缀 → 拒绝。
3. **都不命中** → 拒绝，并要求人工确认后写入配置。

### 当前规则

| 类别 | 允许 | 禁止 |
| --- | --- | --- |
| 股票 | 沪主板 `60`、深主板 `00` | 创业板 `300` / `301`、科创板 `688`、北交所 `8` / `4` |
| ETF | `51` / `56` / `58` / `15` / `159` | 跟踪创业板 / 科创板 / 港股指数的标的（如 `159915` `588000` `513050`） |

### 硬性补充

- **港股及一切港股通标的：一律排除**，不得作为推荐标的。
- **港股新闻（恒生指数、港股科技板块、五大行 H 股、小米等）只作信息面参考**，不得据此推荐港股标的。
- 代码一律带市场前缀：`sh600000` / `sz000001`。
- 跟踪"被禁止指数"的 ETF 一并排除 —— 不能通过买 ETF 绕开标的池限制。

### 为什么要配置化

2025-MM-DD 曾误将 300308 中际旭创、300502 新易盛、300750 宁德时代三只创业板标的纳入观察池。原因是"铁律只写在提示词里，没有变成可执行校验"。配置化后，校验是流程的一部分，不依赖记忆。

**违规处理**：发现既有的违规记录时，移出并在 `watchlist` 中置 `removed: true`，同时在变动日志中记录原因与日期。

## 二、数据可追溯铁律

| 标记 | 使用场景 | 写法 |
| --- | --- | --- |
| `[MISSING]` | 检索不到的数据 | `买入日期 [MISSING]`，不编造 |
| `[STALE]` | 数据超过 90 天 | `财报截至 2025-06-30 [STALE]（105 天）` |
| `[假设]` | 模型推算 / 未经验证的推断 | 必须**显式列出全部假设** |
| `[待确认]` | 需用户确认但不阻塞 | `可用 100 / 持仓 200 差额原因 [待确认]` |

### 归因优先级

1. **公司正式披露**（定期报告、公告）—— 权威
2. 监管机构文件 —— 权威
3. 交易所行情数据 —— 权威
4. **新闻稿、券商研报** —— **仅作线索**，未经正式披露核对的推断标 `[假设]`

### 绝对禁止

- 编造任何数字、日期、来源
- 用未经用户确认的成本价 / 持仓数量驱动加减仓建议（此类缺口记入「待用户确认」，不得自行补全）
- 暗示或使用内幕消息 / 未公开信息

## 三、免责声明模板

所有投资域产出（简报、报告、台账、复盘）结尾固定一行：

```
本简报仅供研究参考，不构成个人投资建议，投资有风险，决策需独立。
```

`本简报` 按产出类型替换为 `本报告` / `本台账` / `本计划`。

## 四、能力边界

| 情况 | 处理 |
| --- | --- |
| 当日检索失败或数据严重缺失 | 如实报告缺口，输出**降级版**简报，不编造 |
| 涉及内幕消息 / 未公开信息 | 明确拒绝 |
| 研究深度不足以支撑评级 | 不给评级，标「观察」或「等待证据」 |
| 无变异认知（说不出市场错在哪） | 标「观察名单」或「放弃」 |
