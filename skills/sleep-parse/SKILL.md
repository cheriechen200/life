# sleep-parse

睡眠报告截图解析，供日报与趋势分析使用。

## 数据定位（重要）

截图解析是**临时记录**：用户当天发来就先落库，保证当天可见、日报可用。截图信息不全属正常，缺的字段如实标注缺失即可，不要估算。

每月一次的 Apple 健康导出包是睡眠的**权威来源**，会用更完整的数据覆盖同月的截图记录（见 `skills/health-import`），因此截图记录只精确到当天的粗略值也没关系。

## 触发场景

- 用户早上起床发来前一夜的睡眠报告截图

## 分析流程

1. 提取入睡时间与起床时间。
2. 提取总睡眠时长。
3. 提取各阶段时长：深睡、浅睡、REM、清醒。
4. 提取睡眠评分（如截图提供）。
5. 组装 `metrics` 并写入 `domains/health/data/sleep/<YYYY-MM>.json`。

## 输出字段

```json
{
  "metrics": {
    "sleep_start": "23:15",
    "sleep_end": "07:00",
    "total_min": 465,
    "deep_min": 95,
    "light_min": 280,
    "rem_min": 90,
    "awake_min": 12,
    "sleep_score": 85,
    "comment": "深睡占比良好，入睡稍晚"
  }
}
```

## 点评规则

- 深睡占比参考：健康范围约 13%-23%
- REM 占比参考：约 20%-25%
- 总时长：成年人推荐 7-9 小时
- 入睡时间：结合用户作息（早 7 点起床）建议 23:00 前入睡

只做结构分析与作息建议，不下医学结论。

## 用户向回报格式

```
睡眠已记录 · 评分 85
23:15 入睡 → 07:00 起床，共 7h45m
深睡 95m / 浅睡 280m / REM 90m
点评：深睡占比良好，入睡稍晚，可尝试提前 15 分钟上床。
```

## 注意事项

- 时间统一 `HH:mm`，时长统一为分钟。
- 截图信息不全时标注缺失字段，不要估算。
- 睡眠归属日期以"起床当天"为准，便于与当天作息对应。
