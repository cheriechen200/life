# water-log

饮水记录。一天内多次记录，每次一条，按 `time` 区分。

## 触发场景

- 用户说「我喝了 2 杯水」「刚喝了一瓶 500ml 的水」「上午喝了三杯」
- 用户发来水瓶 / 水杯的照片（需用户说明容量，或按已知容器口径换算）
- 用户问「今天喝了多少水」（此时**只查不记**，直接读当日记录汇总回报）

## 已知容器口径（用户已确认，无需每次重申）

| 容器 | 容量 | 生效日 |
| --- | --- | --- |
| **办公室杯** | **700 ml** | 2025-MM-DD（**用户更正：原记 550 ml 有误**） |
| 标准矿泉水瓶 | 550 ml | 2025-MM-DD |
| 一次性纸杯（饮水机常见） | **250 ml** | 2025-MM-DD 生效；**2025-10-20 用户已确认，待确认解除** |
| **美式咖啡一杯** | **250 ml** | **2025-10-20 用户确认：公司美式就是一次性纸杯大小** → 按一次性纸杯 250 ml 计，**不再取 350 ml**（MM-DD 的「约 350ml，待确认」口径作废；当日曾据此误订为 350，已回滚） |

用户说「一杯水」而上下文在办公室 / 未指明容器时，**默认按办公室杯 700 ml**。容器未说明且无法从上表推断时，**先确认容量，不要猜**；确需估算时按上表取值并在 `note` 标注「待确认」。

## 晨间固定流程（优先套用）

用户每个工作日的早晨是固定流程（起床温水 → 骑行 → 半截香蕉 → 到司温水 → 美式咖啡 → 训练期间喝咖啡 → 练后餐 → 上午上班喝水）。完整默认量与时间推定规则见 [`domains/health/reference/morning_routine.md`](../domains/health/reference/morning_routine.md)。

**用户说「照常 / 按流程」时直接按该表默认量落库**（上午基线 1250 ml），只确认差异项，不逐项追问。

## 每日目标（用户已确认的口径）

| 场景 | 饮品目标 | 折合 700ml 办公室杯 | 全天总水量（含食物约 600ml） |
| --- | --- | --- | --- |
| **训练日** | **2500 ml** | 约 3.6 杯（实操按 4 杯） | 约 3100 ml |
| **休息日** | **2100 ml** | 3 杯 | 约 2700 ml |

目标是**绝对毫升数**，换杯子不影响目标，只影响杯数换算。

**2025-MM-DD 起**：医生要求**增饮水**护肾（体检肌酐偏高，见 `reports/health/topics/营养目标调整_2025-MM-DD.md`）。目标值暂不变，但**完成度 <70% 按当天必须补齐级别提醒**，不再是「留意」级。

判定训练日 / 休息日：读 `domains/health/data/workouts/<YYYY-MM>.json` 中当日是否有记录（含任何 `type = workout`）。当日有训练即为训练日。

完整排程见 [`reports/health/topics/饮水方案_2025-MM-DD.md`](../reports/health/topics/饮水方案_2025-MM-DD.md)。

## 记录流程

1. **判意图**：用户只是在**问**喝了多少（「我今天喝了多少水」「水喝够了吗」）→ **只汇总回报，不落库**。用户是在**陈述喝了水** → 落库。
2. **换算**：杯数 × 容器容量 = `amount_ml`。用户直接给了 ml 就用给定值。
3. **估时间**：用户未说明时间时，按口述时刻记，并在回报中说明是估记。
4. **读当日已有记录**：累加得到当日累计，计算距目标的差额与完成度。
5. **写入** `domains/health/data/water/<YYYY-MM>.json`（不存在则创建数组）。
6. **跑刷新**：`python3 scripts/normalize_health_data.py`。

## 输出字段

```json
{
  "date": "2025-MM-DD",
  "time": "09:30",
  "domain": "health",
  "type": "water",
  "metrics": {
    "amount_ml": 550,
    "container_ml": 550,
    "containers": 1.0,
    "source_type": "manual",
    "comment": "办公室杯 1 杯，上午第一杯"
  },
  "note": "",
  "source": "",
  "created_at": "2025-MM-DDT09:30:00+08:00"
}
```

`source_type`：`manual`（口述）/ `photo`（照片）/ `apple_health`（导出包）。无附件时 `source` 留空字符串。

## 用户向回报格式

```
饮水已记录 · 700 ml（办公室杯 1 杯）· 09:00
今日累计 1300 ml / 目标 2500 ml（训练日）· 完成 52%
还差 1200 ml ≈ 1.7 杯
```

汇总类回报（用户只问不记）时：

```
今日饮水 1300 ml / 目标 2500 ml · 完成 52%
还差 1200 ml ≈ 1.7 杯 · 按排程下午还应喝 550 ml
```

## 点评规则（针对当前用户）

以下情况值得提醒，但**只做提示，不下医学结论**：

- **服用肌酸 5 g/天**：肌酸靠肌内储水起作用，饮水不足会打折且易抽筋。累计明显落后时可提醒。
- **当日钠偏高**（读当日 meals 的 `sodium_mg` 合计 > 2000 mg）：**要喝多而不是喝少**——肾脏排钠需要水做载体，缺水反而加重水潴留。
- **纤维摄入高**（> 20 g）：纤维需吸水膨胀，缺水反而便秘。
- **睡前 2 小时**（用户入睡约 00:30，即 22:30 之后）：提示递减，避免起夜打断睡眠。

**不要**把「口渴感」当唯一依据——用户久坐办公（步数常低于 1000），坐着不动时口渴感迟钝。

## 注意事项

- 单次饮水量**不要合并**：多次喝就记多条，靠 `time` 区分，这样才看得出分布。
- 用户说「喝了一整壶 / 一大瓶」但未给容量时，**先确认**，不要猜。
- 茶、咖啡、无糖饮料**计入**饮品；牛奶、豆浆、汤、粥**计入食物含水**，不计入本类型。
- 只在用户明确陈述已喝时才落库；不要根据「应该喝了多少」反推记录。
