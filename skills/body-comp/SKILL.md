# body-comp

InBody 人体成分分析报告解析。用于跟踪体成分的长期变化，是"薄肌"目标的核心测量依据。

## 触发场景

- 用户发来 InBody / 体成分分析报告照片（健身房、体检中心）
- 用户说"记录一下体测""更新身体数据"

## 报告识别要点

InBody 报告版式随设备型号与年代变化，解析时按语义定位，不要按固定坐标硬读：

- 表头识别：编号 / ID、年龄、身高、性别、日期、时间、测试机构。
- 「身体成分」区：体重、骨骼肌、体脂肪、身体水分、去脂体重。
- 「肥胖分析」区：BMI、体脂百分比（PBF）、腰臀比（WHR）、基础代谢。
- 「肌肉-脂肪控制」区：肌肉控制、脂肪控制、内脏脂肪等级、健康评估（InBody 评分）。
- 「研究项目」区：去脂体重、基础代谢率、肥胖度、建议热量摄入。
- 「肌肉均衡」/「节段肌肉」区：左右上肢、左右下肢、躯干。
- 「节段脂肪分析」区：左右上肢、左右下肢、躯干的脂肪量与百分比。

注意：OCR 与图片描述都可能出现数字错位，务必以图中标注的数值与其作画位置为准，交叉校验（如 `体重 = 去脂体重 + 体脂肪`、`体脂百分比 = 体脂肪 / 体重`）。无法确定的字段留空，不要编造。

## 分析流程

1. 提取基础信息：日期、时间、年龄、性别、身高、设备型号、编号。
2. 提取核心体成分：体重、骨骼肌、体脂肪、体脂百分比、BMI、腰臀比、基础代谢。
3. 提取控制建议与评分：肌肉控制、脂肪控制、内脏脂肪等级、InBody 评分。
4. 提取水分与去脂体重。
5. 若报告含节段数据，提取节段肌肉与节段脂肪。
6. **跑强制交叉校验**（见下节，不通过不许落库）。
7. 按下方字段组装 `metrics`，写入 `domains/health/data/body_comp/<YYYY-MM>.json`。

## 强制交叉校验（落库前必做）

**2025-MM-DD 事故教训**：MM-DD 那次是二手转录录入，`whr` / `bmr_kcal` / `muscle_control_kg` / `device` **四项全错**，且错误数据被下游文档引用两周，导致一条结论被推翻（WHR「反向上升」实为回落）。因此：**凡有原始报告照片，一律逐字段对照原图直读，不要凭截图摘要或记忆二次转写。**

落库前逐条检查，任一项不通过就先向用户确认，不许落库：

| 校验式 | 容差 |
| --- | --- |
| `体重 ≈ 去脂体重 + 体脂肪` | ±0.15 kg |
| `体脂百分比 ≈ 体脂肪 / 体重 × 100` | ±0.3 pt |
| `BMI ≈ 体重 / (身高m)²` | ±0.3 |
| `去脂体重 ≈ 身体水分 + 蛋白质 + 矿物质` | ±0.5 kg（差值主要是糖原等固形物） |
| `目标体重 ≈ 体重 + 肌肉控制 + 脂肪控制` | ±0.3 kg |
| `节段肌肉五段合计 → 仅作参考` | **不得**与 `骨骼肌` 直接相等（节段口径含去脂软组织，通常大于骨骼肌） |

**四个高危字段**（历史出错过的，转录后必须回原图复核一遍）：

- `whr`（腰臀比）——错 0.06 就会让趋势方向反转
- `bmr_kcal`（基础代谢）——错 60 kcal 会误判代谢下滑
- `muscle_control_kg`——极易与 `fat_control_kg` 抄成同一个数
- `device`——`InBody` 与 `InBody270` 混记会让口径判断失真

## 节段数据的使用边界（重要）

`segmental_muscle` / `segmental_fat` **只能看大方向，不能做跨报告的细颗粒度比较**。

原因：实测中同一人相邻两次测量，五段肌肉合计可差 2–3 kg（如 MM-DD 为 54.57、MM-DD 为 58.35、MM-DD 为 55.98），而同期整体骨骼肌只差 0.5 kg——**偏高只出现在节段拆分上**，属拆分算法边界漂移或当日 hydration 影响，不是真实肌肉变化。

因此：
- 判断"某部位肌肉掉了没有"，**优先看训练记录**（该部位练了几次），不要单靠节段数据下结论。
- 若必须引用节段数据做对比，**至少跨两次以上测量取较长区间**，并在结论旁注明可比性受限。
- 单凭一次节段差值（如"腿掉了 0.9kg"）得出的结论，**必须标注为待核实**。

## 数据订正流程

用户拿来原始报告说"之前的数据有误"时：

1. 逐字段比对原图，列出差异清单（哪些改、从什么改到什么）。
2. 原地更新记录并打 `updated_at`，**不新增记录**。
3. `note` 里写明订正来源与时间（如"以 2025-MM-DD 用户提供的原始报告照片为准订正"），保留原错误值便于追溯。
4. **反向排查下游文档**：`reports/` 与 `data/daily/` 中所有引用该次记录的表、结论、推算都要同步重写，并在文档顶部加订正说明。
5. 同步 `skills/body-comp/SKILL.md` 与 `schema/data-schema.md` 里的**示例模板值**——模板若是错的，后续照抄会持续出错。

## 对标"薄肌"目标的点评规则

用户目标是"薄肌"：低体脂前提下保有清晰肌肉线条。点评围绕：

- 体脂百分比：男性理想区间约 10%-15%；低于 10% 提示脂肪储备不足，警惕激素与恢复受影响。
- 骨骼肌：与历史对比是否有流失；下滑则提示加强力量训练与蛋白质摄入。
- 躯干脂肪：即便总体脂正常，躯干（腹部）超标准也应加强核心与有氧。
- 肌肉均衡：左右 / 上下是否对称，明显失衡时提醒单侧强化。
- 内脏脂肪等级：≤ 9 为健康区间。

只做体成分结构分析，不下医学结论。

## 用户向回报格式

```
体成分已记录 · 2025-MM-DD · InBody 评分 80
体重 70.0kg · 骨骼肌 32.0kg · 体脂 17.0%（12.0kg）
BMI 24.2 · 腰臀比 0.91 · 内脏脂肪 5 级 · 基础代谢 1736kcal
点评：体脂率正常，肌肉量优秀；躯干脂肪 110.7% 超标准，建议加强核心与有氧。
```

## 注意事项

- 一份报告 = 一条记录，日期以报告的测试日期为准（不是拍摄日期）。
- 同一天重复测量时保留最新一条，避免重复记录。
- 报告取自不同设备时，`device` 字段如实记录，便于区分数据来源与口径差异。
- 部分老报告缺少 `whr`、`target_weight_kg`、节段数据等字段，缺失即省略，不要填 0。
- 不得修改用户未提供的数值；OCR 存疑的字段向用户确认。
